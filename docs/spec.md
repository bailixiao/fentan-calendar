## 1. 一句話目標

把**宏教分壇**自己的活動，和底下 16 區的活動，放在同一個行事曆上，家人們可以依區篩選。第一階段**只看、不報名**；教全區的活動附「到教全區報名」按鈕，連到教全區自己的報名系統。

## 2. 整體方向與階段（2026/10/12 討論）

- 三層：**分壇 → 16 區 → 家人**。家人看「分壇＋自己區」的行事曆。
- 長期：一套系統分成 16 區（不是複製 16 份），每區資料分開存、權限分開。
- 階段：
  1. **第一階段（本文件）：分壇總覽**：一個網站把分壇和各區的活動合在一起顯示，可以依區篩選。只看，不報名。
  2. 第二階段：把教全區的系統改成可以放很多區（教全區當第一區，再找第二區試）。到時再決定在哪個專案做。
  3. 第三階段：分壇活動跨區報名、分壇加總統計、分壇推播給 16 區。
- 給第二、三階段的提醒：跨區報名會有大量寫入，建議**每一區一個 Durable Object**（各區分開排隊、資料分開存），不要全部擠在同一個。

## 4. 活動的來源

| 來源 | 單位 | 怎麼進來 |
|---|---|---|
| 分壇自己的活動 | 分壇 | 管理者在後台新增 |
| 教全區的活動 | 教全區 | **自動**從教全區的公開 API 讀進來，不用重複輸入；後台**不能**手動新增教全區的活動 |
| 其他 15 區的活動 | 各區 | 還沒有系統，先由管理者在後台幫他們輸入。每筆標明是哪一區 |

### 類別（照教全區的做法）

每筆活動有一個類別：**勤務**（顯示為「總務・勤務」，赭紅）、**道務**（紫）、**教育**（藍綠）。內部代號就是「勤務／道務／教育」，顯示的名字在 `site.js` 的 `categoryLabels`。

### 讀教全區的資料

- 教全區的公開 API：`https://duty-calendar-api.duty-calendar-worker.workers.dev/?action=getEvents&from=yyyy-MM-dd&to=yyyy-MM-dd`（不用登入，CORS 開放）。
- **由分壇的 Worker 去讀，不讓前端直接讀**：教全區的回應裡有真實人名（管理者聯絡人、借場地的人、組長、師資等），分壇 Worker 只留下面這些欄位，其他一律丟掉：
  `id`、`name`、`category`、`nature`、`mode`、`start`、`end`、`startTime`、`endTime`、`location`、`attire`。
- 借場地（`venue`）不顯示。
- **全部類別都顯示**（勤務、道務、教育）。
- 依「年」去讀（`Y-01-01`～`Y-12-31`），每一年的結果在 Worker 記憶體保留 **5 分鐘**，不管分壇有多少人在看，打到教全區的請求每年份每 5 分鐘最多一次。
- 讀不到（逾時 8 秒、錯誤）時：有上次讀到的就繼續用上次的；沒有就只顯示其他活動，畫面提示「教全區的活動暫時讀不到」。
- 「到教全區報名」連結：`https://bailixiao.github.io/duty-calendar/#/duty/<教全區的 id>?date=<那一天>`。只有「報名型」顯示這個按鈕；公告型寫「到教全區看詳情」。

## 5. 使用者與權限

| 角色 | 權限 |
|---|---|
| 家人們 | 看行事曆，**不用登入** |
| 總管理者 | 新增、修改、刪除分壇與各區（教全區除外）的活動；下載備份 |

- 之後可以加「某區的帳號」，只能改自己區的活動（第一階段不做，但資料已經有「單位」欄，不用改資料格式）。
- 管理密碼放在 Cloudflare Worker 的 secret `ADMIN_PASSWORD`（由使用者自己用 `npx wrangler secret put ADMIN_PASSWORD` 設定），**不寫進程式碼，Claude 不經手真的密碼**。
- 登入後拿到通行碼（隨機 32 bytes），存在 Durable Object，**12 小時**後失效；登出時刪除。
- 連續輸錯密碼 10 次，暫停登入 15 分鐘（防猜密碼）。

## 6. 技術架構

| 層 | 技術 | 說明 |
|---|---|---|
| 前端 | 單一 HTML/CSS/JS，放 GitHub Pages（`https://bailixiao.github.io/fentan-calendar/`） | 手機優先，可以加到主畫面（PWA） |
| 後端 | Cloudflare Worker `fentan-calendar-api` ＋ Durable Object（SQLite） | 資料只存在 Cloudflare；不用 Google 試算表 |
| 行事曆元件 | FullCalendar（CDN，固定版本） | 年、月檢視；週、近期是自製列表 |
| 農曆 | lunar-javascript（CDN，固定版本） | 格子顯示農曆 |

### 負荷設計（分壇的使用量預計是教全區的數十倍）

- 第一階段幾乎只有讀取；寫入只有管理者，一天幾十筆以內。
- 網頁檔案放 GitHub Pages，不算 Cloudflare 用量；只有「拿活動資料」算。
- **Worker 記憶體快取**：分壇自己輸入的活動整份在 Worker 記憶體保留 **60 秒**，同一分鐘內再多人看，也只問 Durable Object 一次。管理者存檔後，自己的畫面用 `fresh=1` 強制拿最新的；其他人最慢 1 分鐘看到。
  （Cloudflare 的 Cache API 在 `workers.dev` 網址上沒有作用，所以用記憶體。）
- 教全區的資料快取 5 分鐘（見第 4 節）。
- 瀏覽器記住上次的資料（localStorage）：再打開先顯示上次的，背景再更新；連不上時也看得到上次的。
- 免費方案每天約 10 萬次請求（Worker、Durable Object 各自計算）。正式上線前到官方定價頁再確認一次；不夠用時改付費方案（每月 5 美元）。

### 時區與日期

- 一律台北時間。日期存 `yyyy-MM-dd` 文字，時間存 `HH:mm` 文字。
- 「今天」由伺服器用台北時間算好，隨資料傳給前端。

## 7. 資料

Durable Object 的 SQLite：

**events（分壇與各區手動輸入的活動）**

| 欄位 | 說明 |
|---|---|
| id | `E-yyyyMMdd-六碼亂數` |
| unit | 「分壇」或 16 區之一（不能是教全區） |
| category | 勤務／道務／教育 |
| name | 活動名稱（必填，最多 60 字） |
| start、end | 開始、結束日期（必填；end ≥ start；最長 60 天） |
| startTime、endTime | `HH:mm`，可以空白 |
| location | 地點（最多 60 字） |
| note | 說明（最多 1000 字） |
| link | 相關連結（選填，只接受 `https://`） |
| batch | 批次匯入的批號（`B-yyyyMMddHHmmss-四碼`）；手動新增的沒有。修改後保留。家人們看不到 |
| createdAt、updatedAt | 台北時間 `yyyy-MM-dd HH:mm:ss` |

**log（操作紀錄）**：時間、動作（新增／修改／刪除）、活動名稱與日期、單位。不記人名。

**sessions**：登入通行碼與到期時間。**props**：登入失敗次數等。

## 8. API（`worker/src/app.js`）

回應格式：`{ ok: true, data }` 或 `{ ok: false, error: { code, message } }`。讀取用 GET；寫入用 POST，內容是 JSON（標頭 `text/plain`，避免 CORS 預檢）。

| 動作 | 方法 | 說明 |
|---|---|---|
| `getEvents` | GET `from`、`to`（最長 400 天），`fresh=1` 跳過手動活動的快取 | `{ from, to, today, events: [...], sources: { 教全區: { ok, stale } } }`。每筆活動：`id`、`source`（`local`／`jiaoquan`）、`unit`、`category`、`name`、`start`、`end`、`startTime`、`endTime`、`location`、`note`、`link`；教全區的另有 `mode`、`nature`、`attire`，`id` 是 `jq-` 加教全區的 id，`link` 是教全區的報名頁（前端再加 `?date=那一天`） |
| `ping` | GET | 健康檢查 |
| `adminLogin` | POST `password` | `{ token, expiresInSec }` |
| `adminLogout` | POST `token` | |
| `adminList` | POST `token` | 全部手動活動（後台列表） |
| `adminSave` | POST `token`、`event`（有 `id` 為修改，沒有為新增） | 檢查欄位，回存好的活動 |
| `adminDelete` | POST `token`、`id` | |
| `adminImport` | POST `token`、`events`（最多 300 筆） | 批次匯入：每筆照 adminSave 的規則檢查，**有一筆錯就整批不存**（錯誤訊息列出第幾筆）；和現有活動重複（同單位、名稱、開始日期、開始時間）的跳過。回 `{ batch, added, skipped }` |
| `adminDeleteBatch` | POST `token`、`batch` | 整批刪除（含匯入後修改過的） |
| `adminLog` | POST `token` | 最近 200 筆操作紀錄 |
| `adminBackup` | POST `token` | 全部活動＋操作紀錄（下載備份用） |

## 9. 畫面

設計沿用教全區：整潔安靜，米白底、深墨色字、赭紅色重點色；標題明體、內文黑體；**按鈕至少 44px、做成按鈕的樣子（不用底線文字連結）**；頁首「A＋」可以放大字體。

### 家人們

1. **行事曆首頁**：年／月／週／近期切換（記住上次的，第一次預設月）。
   - 月：格子顯示國曆＋農曆與色點；點日期在下方列出當天活動卡片。
   - 年：12 個月，點日期跳到那個月；今年已過的月份預設收起。
   - 週：七天直向列出。
   - 近期：今天起一個月有活動的日子依序列出。
2. **單位篩選**（行事曆上方，記住選擇）：下拉選單「分壇的活動／教真區⋯教理區」，**預設「分壇的活動」**。
   - 選「分壇的活動」只看分壇的，看不到各區的（2026/10/13：沒有「全部」這個選項，分壇不需要看到各區的活動）。
   - 選某一區時，下面多一個勾選「也顯示分壇的活動」（預設勾，符合「家人看分壇＋自己區」）。
   - 以前選過「全部」的手機，自動改成「分壇的活動」。
3. **色點與標籤**：色點顏色依類別（勤務赭紅、道務紫、教育藍綠）；分壇的活動色點外面多一圈金色框。卡片標題上方有「單位」標籤（分壇是金底，各區是灰底）＋類別標籤。
4. **活動詳情**（`#/event/<id>?date=yyyy-MM-dd`）：單位、類別、名稱、日期（含農曆）、時間、地點、服裝（教全區才有）、說明、相關連結。教全區的活動有大按鈕「到教全區報名」（另開分頁）。
5. **常見問題**（`#/help`）：怎麼看、怎麼篩選、怎麼加到手機主畫面、活動資料從哪裡來、怎麼報名。
6. 頁尾有「管理者」小按鈕。

### 管理後台（`#/admin`）

1. **登入**：只有密碼欄（顯示／隱藏密碼）。
2. **活動列表**：預設今天起的活動，可切換「已過去的」；依單位篩選、搜尋名稱；每筆有「修改」「另存新的」「刪除」（刪除要確認）。
3. **新增／修改**：單位（分壇＋15 區，沒有教全區）、類別、名稱、開始日期、結束日期（預設同一天）、開始時間、結束時間、地點、說明、相關連結。存檔前在前端檢查，伺服器再檢查一次。
4. **批次匯入**（`#/admin/import`，2026/10/13）：其他區的活動由 Claude 整理成匯入檔（JSON：`{ title, events: [{ unit, category, name, start, end, startTime, endTime, location, note, link }] }`），管理者上傳 → 預覽（✓ 可以匯入、紅色有錯並寫出原因、「已經有了」會跳過）→ 沒有錯才出現「匯入 N 筆」。下面列出「最近匯入的批次」（時間、筆數、單位、日期範圍），可以「刪除這批」。匯入檔放在 `imports/`（不進儲存庫）。
5. **操作紀錄**：最近 200 筆（匯入、整批刪除各記一筆，寫筆數和單位）。
6. **下載備份**：下載 `fentan-calendar-backup-yyyyMMdd.json`（全部活動＋操作紀錄）。

## 10. PWA 與快取

- `manifest.webmanifest`：名稱「宏教分壇行事曆」，`start_url`、`scope` 都是 `./`。
- Service Worker（`sw.js`）：做法同教全區。**快取名稱帶網站路徑**（`fentan-calendar:/fentan-calendar/:v1`），清舊快取時只清自己的，不動同網域其他網站（教全區、書槑子）的快取。資料 API 不經過 Service Worker。

## 9-1. 各區報名連動（2026/10/13）

- 方向：分壇行事曆是**統計端**，不直接收報名。**各區家人在各區自己的系統報名**，分壇自動讀過來，看到每區有沒有人報、報了誰（不用各區再回報一次）。**名單大家都看得到**（和教全區一樣）。
- 目前只有教全區有報名系統，所以先連動教全區；其他區有系統後（第二階段：把教全區的系統改成可以放很多區），用同樣的方式接上。
- **狀態的算法和教全區相同**：公告型寫「輪值：第 N 組」或「公告」；道務、教育自由參加，寫「已報 N 人」（滿了寫「額滿」）；勤務照每個了愿項目的最少人數（沒填算 2 人）算缺幾人，寫「缺 N 人」／「額滿」／「人數足・N 人」（都不限名額的寫「已報 N 人」）。
- **行事曆卡片**：教全區的活動右邊顯示那一天的狀態。
- **活動詳情**：教全區的活動列出那一天（多天的列每一天）每個了愿項目報名的名字。
- **「📊 報名統計」頁**（`#/signups`，行事曆上方按鈕）：分壇行事曆偏向**統計端**（2026/10/13：很少直接向分壇報名，都是各區統計完給分壇）。最上面是總數（幾個活動、共幾人次、幾項缺人），可依區篩選；下面依日期列出今天起 30 天內各區的活動、狀態和名單，同一天缺人的排前面。目前只有教全區的資料。
- 讀法：教全區的 `getEvents`（已經在讀）有每天的人數；名單用教全區的 `getBundle`（今天起 30 天、一次拿全部）和 `getDuty`（30 天以後的單一活動）。**分壇只讀名字**（2026/10/13）：只留了愿項目名稱、日期、名字；陪同、佛堂、備註、組長、電話等都丟掉。分壇 Worker 記憶體快取：`getBundle` 5 分鐘、`getDuty` 2 分鐘。
- API：`getSignups`（GET，30 天內有報名的教全區活動與名單）、`getRoster`（GET `id`，單一教全區活動的名單）。
- **各區報名系統**（第二階段，2026/10/13 上線，另一個專案 `D:Projects各區報名系統`，`https://bailixiao.github.io/region-signup/`）：報名統計也讀它的 `feed`（今天起 30 天、**開放**的區），和教全區一起列；點活動打開該區的報名頁。快取 2 分鐘；讀不到時教全區照常顯示。網址加 `?test=1`（`#/signups?test=1`）連「測試」的區（含測試區）一起，給測試連動用。

## 9-2. 分壇分配的勤務帶到各區報名系統（2026/10/13）

- 分壇派給各區的勤務**只存在分壇行事曆一份**；各區報名系統自動讀過來讓家人報名（報名存在各區系統），報名統計再讀回來。區管理者不能改分壇分配的勤務。
- 活動多兩個欄位：
  - `kind`：單位是某一區時，「**分壇分配**」（預設）或「**區活動**」（只是記在分壇行事曆上，不帶到各區系統；例如範例資料）。單位是分壇的不用填。
  - `positions`：了愿項目與名額（選填，規則同各區報名系統：名稱、最少、最多，最多 10 個）。沒填的到各區系統預設「參加」、不限人數。
- 後台**新增**活動時，單位可以一次勾好幾區（每區各一筆，同一個批號，可以整批刪除）；修改時一次只改一筆。
- 後台表單**不提供**選「區活動」（2026/10/13：派給區的一定是分壇分配）。「區活動」只用在匯入的範例資料；修改這種活動時維持「區活動」，畫面註明不會帶到各區報名系統。
- 單位多一個「**測試區**」（只在後台出現，分壇行事曆上不顯示），用來試各區報名系統的連動。
- 公開的 `getEvents` 多回傳 `kind`、`positions`。

## 10-1. 手機提醒（推播，2026/10/13）

原本排在第三階段的「分壇推播給 16 區」提前做。做法參考教全區（Web Push，通知不帶內容，手機收到後回伺服器問要顯示什麼，所以不用加密）。

### 家人們
- 行事曆上方「🔔 手機提醒」：選「要收哪個單位的提醒」（分壇或某一區，預設是行事曆目前選的單位）→ 開啟。可以改單位、關閉、傳測試通知（同一支手機 30 秒內只能傳一次）。
- 只存推播網址和選的單位，**不存名字**。
- iPhone／iPad 要先「加入主畫面」、從主畫面打開才能開啟（iOS 16.4 以上），沒加的話畫面說明步驟。通知一定要本人按允許。
- 推播網址只接受各家推播服務（fcm.googleapis.com、*.push.apple.com、*.push.services.mozilla.com、*.notify.windows.com），擋掉其他網址，避免伺服器被拿去連任意網站。

### 自動提醒
- 每天台北時間**晚上 8 點提醒明天、早上 7 點提醒今天**的活動。
- 選某一區的手機：那一區＋分壇的活動；選分壇的手機：只有分壇的。教全區的手機也包含從教全區讀進來的活動。
- 那天沒有活動的單位不送。內容：標題「🙏 明天的活動（10/14 三）」，列前 4 項（時間、名稱、地點），超過寫「⋯還有 N 項」。點通知打開行事曆。

### 管理者手動發（後台「📣 發通知」分頁）
- 寫標題、內容；對象選**全部**、**只發分壇的**，或勾選某幾區（可多選）；可以「馬上發」或「排定時間」（台北時間，10 分鐘後～30 天內）。
- 送出前顯示「大約會送到 N 支手機」（各單位目前開啟提醒的手機數）。
- 列出最近 50 則：時間、對象、內容、狀態（排定／送出中／已送出／已取消）、成功與失敗數；排定的可以取消。寫入操作紀錄。
- 標題最多 40 字、內容最多 200 字。

### 後端
- 簽章金鑰（VAPID，ECDSA P-256）第一次用到時由 Durable Object 用 WebCrypto 產生，存在它的 SQLite，不寫進程式碼。換金鑰會讓所有手機都要重新開啟。
- 送出：每支手機要顯示的內容先存到「收件匣」（12 小時後過期），再送一個空的推播；手機的 Service Worker 收到後用自己的代號（推播網址 SHA-256 前 16 碼）問 `pushSummary`，拿到內容再顯示。
- **分批送**：Cloudflare 免費方案一次執行最多對外連 50 次，所以每批送 40 支，用 Durable Object 的 alarm 接著送下一批，直到送完。失效的（404／410）自動刪除。
- 排程：**全部用 Durable Object 的 alarm**，不用 cron（Cloudflare 免費方案整個帳號最多 5 個 cron，教全區已經用掉了）。「下一次每日提醒」記在 props，alarm 設在它和送出工作之中比較早的那個；每次響完排下一次。第一次部署後，任何一個 API 請求都會把每日提醒排上。alarm 遲到超過 2 小時的每日提醒就不送。
- API：`pushKey`（GET，公鑰）、`pushSummary`（GET `id`）、`pushSubscribe`（POST `endpoint`、`unit`）、`pushUnsubscribe`、`pushTest`；後台 `adminPushStats`、`adminPushSend`、`adminPushList`、`adminPushCancel`。
