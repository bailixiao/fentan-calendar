> 本文件是給開發者（含 Claude Code）的完整需求說明。所有開發都以本文件為準，需求有變動時先更新本文件。
> 本儲存庫是**公開的**（GitHub Pages 免費方案只能用公開儲存庫），因此**任何人名、電話都不可以出現在程式碼、測試資料、文件或 commit 訊息中**。測試用明顯的假名（測試甲、王小明）。區名是公開資訊，可以放進程式。

## 1. 一句話目標

把**宏教分壇**自己的活動，和底下 16 區的活動，放在同一個行事曆上，家人們可以依區篩選。第一階段**只看、不報名**；教全區的活動附「到教全區報名」按鈕，連到教全區自己的報名系統。

## 2. 整體方向與階段（2026/10/12 討論）

- 三層：**分壇 → 16 區 → 家人**。家人看「分壇＋自己區」的行事曆。
- 長期：一套系統分成 16 區（不是複製 16 份），每區資料分開存、權限分開。
- 階段：
  1. **第一階段（本文件）：分壇總覽**：一個網站把分壇和各區的活動合在一起顯示，可以依區篩選。只看，不報名。
  2. 第二階段：把教全區的系統改成可以放很多區（教全區當第一區，再找第二區試）。到時再決定在哪個專案做。
  3. 第三階段：分壇活動跨區報名、分壇加總統計、分壇推播給 16 區。
- 給第二、三階段的提醒：跨區報名會有大量寫入，建議**每一區一個 Durable Object**（各區分開排隊、資料分開存），不要全部擠在同一個。

## 4. 活動的來源

| 來源 | 單位 | 怎麼進來 |
|---|---|---|
| 分壇自己的活動 | 分壇 | 管理者在後台新增 |
| 教全區的活動 | 教全區 | **自動**從教全區的公開 API 讀進來，不用重複輸入；後台**不能**手動新增教全區的活動 |
| 其他 15 區的活動 | 各區 | 還沒有系統，先由管理者在後台幫他們輸入。每筆標明是哪一區 |

### 類別（照教全區的做法）

每筆活動有一個類別：**勤務**（顯示為「總務・勤務」，赭紅）、**道務**（紫）、**教育**（藍綠）。內部代號就是「勤務／道務／教育」，顯示的名字在 `site.js` 的 `categoryLabels`。

### 讀教全區的資料

- 教全區的公開 API：`https://duty-calendar-api.duty-calendar-worker.workers.dev/?action=getEvents&from=yyyy-MM-dd&to=yyyy-MM-dd`（不用登入，CORS 開放）。
- **由分壇的 Worker 去讀，不讓前端直接讀**：教全區的回應裡有真實人名（管理者聯絡人、借場地的人、組長、師資等），分壇 Worker 只留下面這些欄位，其他一律丟掉：
  `id`、`name`、`category`、`nature`、`mode`、`start`、`end`、`startTime`、`endTime`、`location`、`attire`。
- 借場地（`venue`）不顯示。
- **全部類別都顯示**（勤務、道務、教育）。
- 依「年」去讀（`Y-01-01`～`Y-12-31`），每一年的結果在 Worker 記憶體保留 **5 分鐘**，不管分壇有多少人在看，打到教全區的請求每年份每 5 分鐘最多一次。
- 讀不到（逾時 8 秒、錯誤）時：有上次讀到的就繼續用上次的；沒有就只顯示其他活動，畫面提示「教全區的活動暫時讀不到」。
- 「到教全區報名」連結：`https://bailixiao.github.io/duty-calendar/#/duty/<教全區的 id>?date=<那一天>`。只有「報名型」顯示這個按鈕；公告型寫「到教全區看詳情」。

## 5. 使用者與權限

| 角色 | 權限 |
|---|---|
| 家人們 | 看行事曆，**不用登入** |
| 總管理者 | 新增、修改、刪除分壇與各區（教全區除外）的活動；下載備份 |

- 之後可以加「某區的帳號」，只能改自己區的活動（第一階段不做，但資料已經有「單位」欄，不用改資料格式）。
- 管理密碼放在 Cloudflare Worker 的 secret `ADMIN_PASSWORD`（由使用者自己用 `npx wrangler secret put ADMIN_PASSWORD` 設定），**不寫進程式碼，Claude 不經手真的密碼**。
- 登入後拿到通行碼（隨機 32 bytes），存在 Durable Object，**12 小時**後失效；登出時刪除。
- 連續輸錯密碼 10 次，暫停登入 15 分鐘（防猜密碼）。

## 6. 技術架構

| 層 | 技術 | 說明 |
|---|---|---|
| 前端 | 單一 HTML/CSS/JS，放 GitHub Pages（`https://bailixiao.github.io/fentan-calendar/`） | 手機優先，可以加到主畫面（PWA） |
| 後端 | Cloudflare Worker `fentan-calendar-api` ＋ Durable Object（SQLite） | 資料只存在 Cloudflare；不用 Google 試算表 |
| 行事曆元件 | FullCalendar（CDN，固定版本） | 年、月檢視；週、近期是自製列表 |
| 農曆 | lunar-javascript（CDN，固定版本） | 格子顯示農曆 |

### 負荷設計（分壇的使用量預計是教全區的數十倍）

- 第一階段幾乎只有讀取；寫入只有管理者，一天幾十筆以內。
- 網頁檔案放 GitHub Pages，不算 Cloudflare 用量；只有「拿活動資料」算。
- **Worker 記憶體快取**：分壇自己輸入的活動整份在 Worker 記憶體保留 **60 秒**，同一分鐘內再多人看，也只問 Durable Object 一次。管理者存檔後，自己的畫面用 `fresh=1` 強制拿最新的；其他人最慢 1 分鐘看到。
  （Cloudflare 的 Cache API 在 `workers.dev` 網址上沒有作用，所以用記憶體。）
- 教全區的資料快取 5 分鐘（見第 4 節）。
- 瀏覽器記住上次的資料（localStorage）：再打開先顯示上次的，背景再更新；連不上時也看得到上次的。
- 免費方案每天約 10 萬次請求（Worker、Durable Object 各自計算）。正式上線前到官方定價頁再確認一次；不夠用時改付費方案（每月 5 美元）。

### 時區與日期

- 一律台北時間。日期存 `yyyy-MM-dd` 文字，時間存 `HH:mm` 文字。
- 「今天」由伺服器用台北時間算好，隨資料傳給前端。

## 7. 資料

Durable Object 的 SQLite：

**events（分壇與各區手動輸入的活動）**

| 欄位 | 說明 |
|---|---|
| id | `E-yyyyMMdd-六碼亂數` |
| unit | 「分壇」或 16 區之一（不能是教全區） |
| category | 勤務／道務／教育 |
| name | 活動名稱（必填，最多 60 字） |
| start、end | 開始、結束日期（必填；end ≥ start；最長 60 天） |
| startTime、endTime | `HH:mm`，可以空白 |
| location | 地點（最多 60 字） |
| note | 說明（最多 1000 字） |
| link | 相關連結（選填，只接受 `https://`） |
| createdAt、updatedAt | 台北時間 `yyyy-MM-dd HH:mm:ss` |

**log（操作紀錄）**：時間、動作（新增／修改／刪除）、活動名稱與日期、單位。不記人名。

**sessions**：登入通行碼與到期時間。**props**：登入失敗次數等。

## 8. API（`worker/src/app.js`）

回應格式：`{ ok: true, data }` 或 `{ ok: false, error: { code, message } }`。讀取用 GET；寫入用 POST，內容是 JSON（標頭 `text/plain`，避免 CORS 預檢）。

| 動作 | 方法 | 說明 |
|---|---|---|
| `getEvents` | GET `from`、`to`（最長 400 天），`fresh=1` 跳過手動活動的快取 | `{ from, to, today, events: [...], sources: { 教全區: { ok, stale } } }`。每筆活動：`id`、`source`（`local`／`jiaoquan`）、`unit`、`category`、`name`、`start`、`end`、`startTime`、`endTime`、`location`、`note`、`link`；教全區的另有 `mode`、`nature`、`attire`，`id` 是 `jq-` 加教全區的 id，`link` 是教全區的報名頁（前端再加 `?date=那一天`） |
| `ping` | GET | 健康檢查 |
| `adminLogin` | POST `password` | `{ token, expiresInSec }` |
| `adminLogout` | POST `token` | |
| `adminList` | POST `token` | 全部手動活動（後台列表） |
| `adminSave` | POST `token`、`event`（有 `id` 為修改，沒有為新增） | 檢查欄位，回存好的活動 |
| `adminDelete` | POST `token`、`id` | |
| `adminLog` | POST `token` | 最近 200 筆操作紀錄 |
| `adminBackup` | POST `token` | 全部活動＋操作紀錄（下載備份用） |

## 9. 畫面

設計沿用教全區：整潔安靜，米白底、深墨色字、赭紅色重點色；標題明體、內文黑體；**按鈕至少 44px、做成按鈕的樣子（不用底線文字連結）**；頁首「A＋」可以放大字體。

### 家人們

1. **行事曆首頁**：年／月／週／近期切換（記住上次的，第一次預設月）。
   - 月：格子顯示國曆＋農曆與色點；點日期在下方列出當天活動卡片。
   - 年：12 個月，點日期跳到那個月；今年已過的月份預設收起。
   - 週：七天直向列出。
   - 近期：今天起一個月有活動的日子依序列出。
2. **單位篩選**（行事曆上方，記住選擇）：下拉選單「全部／分壇／教真區⋯教理區」。
   - 選某一區時，下面多一個勾選「也顯示分壇的活動」（預設勾，符合「家人看分壇＋自己區」）。
3. **色點與標籤**：色點顏色依類別（勤務赭紅、道務紫、教育藍綠）；分壇的活動色點外面多一圈金色框。卡片標題上方有「單位」標籤（分壇是金底，各區是灰底）＋類別標籤。
4. **活動詳情**（`#/event/<id>?date=yyyy-MM-dd`）：單位、類別、名稱、日期（含農曆）、時間、地點、服裝（教全區才有）、說明、相關連結。教全區的活動有大按鈕「到教全區報名」（另開分頁）。
5. **常見問題**（`#/help`）：怎麼看、怎麼篩選、怎麼加到手機主畫面、活動資料從哪裡來、怎麼報名。
6. 頁尾有「管理者」小按鈕。

### 管理後台（`#/admin`）

1. **登入**：只有密碼欄（顯示／隱藏密碼）。
2. **活動列表**：預設今天起的活動，可切換「已過去的」；依單位篩選、搜尋名稱；每筆有「修改」「另存新的」「刪除」（刪除要確認）。
3. **新增／修改**：單位（分壇＋15 區，沒有教全區）、類別、名稱、開始日期、結束日期（預設同一天）、開始時間、結束時間、地點、說明、相關連結。存檔前在前端檢查，伺服器再檢查一次。
4. **操作紀錄**：最近 200 筆。
5. **下載備份**：下載 `fentan-calendar-backup-yyyyMMdd.json`（全部活動＋操作紀錄）。

## 10. PWA 與快取

- `manifest.webmanifest`：名稱「宏教分壇行事曆」，`start_url`、`scope` 都是 `./`。
- Service Worker（`sw.js`）：做法同教全區。**快取名稱帶網站路徑**（`fentan-calendar:/fentan-calendar/:v1`），清舊快取時只清自己的，不動同網域其他網站（教全區、書槑子）的快取。資料 API 不經過 Service Worker。
- js、css 網址帶 `?v=日期`，改了就換新日期。

## 11. 開發流程

- 每完成一段就 commit 並 push。
- `node --test` 跑全部測試（`tests/worker.test.mjs`：Worker 的邏輯，用記憶體版的資料存放、假的教全區 API，不用連網；`tests/site.test.mjs`：前後端設定一致、Service Worker 快取名稱、版本號）。
- 本機預覽：`node tools/dev-server.js --mock`（跑同一份 Worker 程式，資料放記憶體，管理密碼 `test-pass`，教全區資料和示範活動都是假資料）。連接埠用環境變數 `PORT`；`.claude/launch.json` 設 `autoPort`，不固定連接埠。
- 每次加新功能或畫面改變，都要同時更新常見問題（`js/help.js`）和截圖（`img/help/`，先開測試版再 `SHOT_BASE=http://localhost:<port>/ node tools/help-shots.js`）。

## 12. 第一階段之後再做

- 從照片讓 AI 整理成草稿（沿用教全區用 Gemini 的做法，金鑰放 Worker secret）。
- 各區帳號（只能改自己區）。
- 推播、跨區報名、統計（第三階段）。
